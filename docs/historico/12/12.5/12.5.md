## Aspectos unificables entre módulos

Algunos aspectos son estructuralmente idénticos entre integrantes y pueden implementarse como un único aspecto compartido:

### Logging (M1–M7)

El advice `around` de logging tiene la misma estructura en los tres integrantes: registra entrada, ejecuta, registra salida o excepción. La única variación es el prefijo de módulo (`[M1]`, `[M2/M3]`, etc.), que puede parametrizarse.

```python
# Un único aspecto configurable para todos los módulos
def logging_aspect(modulo: str):
    def decorator(func):
        async def wrapper(*args, **kwargs):
            logger.info(f"[{modulo}] → {func.__name__}")
            start = time.monotonic()
            try:
                result = await func(*args, **kwargs)
                logger.info(f"[{modulo}] ✓ {func.__name__} ({time.monotonic()-start:.2f}s)")
                return result
            except Exception as e:
                logger.error(f"[{modulo}] ✗ {func.__name__} — {type(e).__name__}: {e}")
                raise
        return wrapper
    return decorator

# Aplicado por módulo:
@logging_aspect("M1")
def parse_data(...): ...

@logging_aspect("M2")
async def join_queue(...): ...

@logging_aspect("M7")
def get_turnos_config(): ...
```

### Validación de sesión (M1, M2, M3)

El aspecto `before` de validación de sesión es idéntico en M1 y M2/M3 — ambos llaman a `get_session(sid)` y lanzan `HTTPException 401`. Puede centralizarse en `src/shared/session_guard.py` y aplicarse a todos los endpoints protegidos del sistema.

```python
# src/shared/session_guard.py — aspecto compartido por M1, M2, M3
def require_session(func):
    async def wrapper(data, *args, **kwargs):
        sid = getattr(data, "sid", None) or kwargs.get("sid")
        session = get_session(sid)
        if not session:
            raise HTTPException(status_code=401, detail="Sesión inválida o expirada")
        kwargs["session"] = session
        return await func(data, *args, **kwargs)
    return wrapper
```

## Resumen por tipo de advice

| Tipo de advice | Aspectos | Cuándo se ejecuta |
|---|---|---|
| **before** | Validación de sesión (M1, M2, M3), Autorización de admin (M6, M7) | Antes de la lógica de negocio — puede abortar con excepción |
| **around** | Logging (M1–M7) | Envuelve toda la ejecución — controla entrada, salida y errores |
| **after-returning** | Publicación de eventos (M3), Invalidación de caché (M7) | Solo si la operación completó sin error |
| **after-throwing** | Manejo de errores en consumers (M4, M5) | Solo si ocurrió una excepción no manejada |
