# 15.5.1. Contexto

Documentación consolidada de arquitectura del Sistema de Comedor UNI (M1–M7) en **Structurizr DSL**. Este archivo contiene el `workspace` completo (modelo + todas las vistas: contexto, contenedores, componentes y despliegue); las subsecciones [15.5.2](../15.5.2/15.5.2.md), [15.5.3](../15.5.3/15.5.3.md) y [15.5.4](../15.5.4/15.5.4.md) referencian las vistas de este mismo workspace. Los renders ya disponibles de los niveles 1–3 están en la [sección 7](../../../7/7.md).

---

## Workspace consolidado (Structurizr DSL)

```structurizr
workspace "Sistema de Comedor UNI" "Modelo C4 consolidado M1-M7" {

    model {
        estudiante = person "Estudiante" "Se autentica, se encola, recibe notificaciones y sigue su turno"
        admin = person "Administrador del comedor" "Configura aforos, horarios y menu (M7)"

        google = softwareSystem "Google Login" "Identidad institucional" "External"
        orce   = softwareSystem "Intranet/ORCE UNI" "Datos y foto vigente del estudiante" "External"
        expo   = softwareSystem "Expo Push" "Entrega de notificaciones push" "External"

        comedor = softwareSystem "Sistema de Comedor UNI" "Gestion de cola, turnos, reasignacion, notificaciones y configuracion" {
            mobile   = container "App Movil" "Login, cola, ticket y notificaciones" "React Native"
            webadmin = container "Web App Administrativa" "UI de configuracion (M7)" "React/TS"

            api = container "API Backend" "Monolito FastAPI: aloja M1, M2, M3, M5 y M7" "FastAPI (Python)" {
                # M1 - Autenticacion
                authRouter  = component "auth.router" "parse-data, verify-biometric, me, logout" "FastAPI"
                authService = component "Servicio de Autenticacion" "Orquesta scraping + biometria + sesion" "Python"
                scraper     = component "Servicio de Scraping" "Datos y foto de ORCE" "Python (bs4)"
                biometria   = component "Servicio de Biometria" "Compara selfie vs foto vigente" "Python (deepface)"
                sessionMgr  = component "Gestor de Sesiones" "sid + blacklist con TTL" "Python + Redis"
                # M2 - Colas
                queueRouter = component "queue.router" "join, status, confirm, leave" "FastAPI"
                validador   = component "Validador de Restricciones" "Sesion + elegibilidad" "Python"
                controlCap  = component "Control de Capacidad" "Contadores atomicos de cupo" "Python + Redis"
                gestorFifo  = component "Gestor FIFO" "Ingreso O(log N) y posicion (ZRANK)" "Redis Sorted Set"
                # M3 - Turnos
                generador    = component "Generador de Turno" "Crea turno desde el ingreso a cola" "Python"
                gestorEstado = component "Gestor de Estado de Turno" "Maquina de estados ACID" "Python"
                auditoria    = component "Auditoria de Turnos" "Registra cada mutacion (Command)" "Python"
                # M5 - Seguimiento
                seguimiento = component "Servicio de Seguimiento" "Estado y posicion del turno" "Python"
                realtime    = component "RealTime Channel" "Empuja estado al cliente" "WebSocket"
                # M7 - Configuracion
                configRouter  = component "config.router" "GET/PUT /config/turnos y /config/menu" "FastAPI"
                configService = component "config.service" "Valida y persiste configuracion" "Python"
                cacheProxy    = component "Proxy de cache" "Cache-Aside + invalidacion dirigida" "Python + Redis"
            }

            workerReasign = container "Worker de Reasignacion" "Ejecuta llamar_siguiente (M6)" "Python" {
                consumerM6 = component "consumer/handler" "Consumo idempotente; ack/nack" "aio-pika"
                reasignSvc = component "reassignment.service" "batch_size, FIFO, SKIP LOCKED" "Python"
            }

            workerInactividad = container "Worker de Inactividad" "Cancela turnos LLAMADO sin ping (M3)" "Python (async)" {
                scheduler = component "Scheduler de Activacion" "Heartbeat ultimo_ping" "Python"
            }

            consumers = container "Consumers M4/M5" "Notificacion y seguimiento asincronos" "Python (aio-pika)" {
                m4       = component "Consumer M4" "Despacha push y registra estado" "Python"
                registro = component "Registro de Notificaciones" "Historial con estado de entrega" "Python"
                m5       = component "Consumer M5" "Persiste eventos de seguimiento" "Python"
            }

            postgres = container "PostgreSQL" "Fuente de verdad: estudiantes, turnos, turno_dia, turnos_config, historial_*" "postgres:15" "Database"
            redis    = container "Redis" "session:{sid} (M1) y turnos_config:cache (M7); cola operativa" "redis:7" "Cache"
            rabbit   = container "RabbitMQ" "Eventos turno.* (M3 -> M4/M5/M6) + DLQ" "rabbitmq:3" "Message Broker"
        }

        # Relaciones de contexto
        estudiante -> mobile "Usa" "HTTPS/WSS"
        admin -> webadmin "Configura" "HTTPS"
        comedor -> google "Valida credencial" "HTTPS"
        comedor -> orce "Obtiene perfil y foto" "HTTPS"
        comedor -> expo "Envia notificaciones" "HTTPS"

        # Relaciones de contenedores
        mobile -> api "REST + WebSocket" "HTTPS/WSS"
        webadmin -> api "PUT/GET /config/*" "HTTPS/JSON"
        api -> postgres "Lee/escribe (ACID)" "SQL/TLS"
        api -> redis "Sesiones, cache, cola operativa" "RESP/TLS"
        api -> rabbit "Publica eventos turno.*" "AMQP"
        rabbit -> consumers "turno.llamado/cancelado/atendido/encolado" "AMQP"
        rabbit -> workerReasign "Evento de cupo liberado" "AMQP"
        consumers -> postgres "Persiste historial" "SQL/TLS"
        consumers -> expo "Envia push" "HTTPS"
        workerReasign -> postgres "SELECT ... FOR UPDATE SKIP LOCKED / UPDATE" "SQL/TLS"
        workerInactividad -> postgres "Cancela inactivos" "SQL/TLS"
        workerInactividad -> rabbit "Publica turno.cancelado" "AMQP"

        # Componentes M1
        authRouter -> authService "Invoca"
        authService -> scraper "Obtiene perfil/foto"
        authService -> biometria "Verifica identidad"
        authService -> sessionMgr "Crea sesion"
        sessionMgr -> redis "SET/GET/DEL con TTL"
        authService -> postgres "Upsert perfil"
        scraper -> orce "Parsea HTML"
        authService -> google "Valida credencial"
        # Componentes M2/M3
        queueRouter -> validador "Valida"
        validador -> controlCap "Verifica cupo"
        controlCap -> redis "INCR/DECR atomico"
        queueRouter -> gestorFifo "Encola"
        gestorFifo -> redis "ZADD/ZRANK"
        queueRouter -> generador "Genera turno"
        generador -> postgres "INSERT turno"
        gestorEstado -> postgres "UPDATE estado (CHECK/indice unico)"
        gestorEstado -> auditoria "Notifica mutacion"
        auditoria -> rabbit "Publica turno.*"
        # Componentes M5
        seguimiento -> postgres "Lee estado/historial"
        seguimiento -> realtime "Notifica cambio"
        # Componentes M6
        consumerM6 -> reasignSvc "Invoca"
        reasignSvc -> postgres "SKIP LOCKED / UPDATE"
        consumerM6 -> rabbit "nack -> DLQ"
        # Componentes M7
        configRouter -> configService "Invoca"
        configService -> cacheProxy "Lee config"
        configService -> postgres "UPDATE turnos_config"
        cacheProxy -> redis "GET/DEL turnos_config:cache"
        cacheProxy -> postgres "Fallback SELECT"
        # Componentes M4
        m4 -> expo "Envia push"
        m4 -> registro "Registra envio"
        registro -> postgres "INSERT historial"
        m5 -> postgres "Persiste evento"

        produccion = deploymentEnvironment "Produccion" {
            deploymentNode "Zona publica" "Internet" {
                deploymentNode "Dispositivo del estudiante" {
                    containerInstance mobile
                }
                deploymentNode "Navegador admin" {
                    containerInstance webadmin
                }
            }
            deploymentNode "Borde / DMZ" "Terminacion TLS" {
                gateway = infrastructureNode "API Gateway / Reverse Proxy" "HTTPS, rate limiting, authN admin" "Nginx/Traefik"
                lb = infrastructureNode "Load Balancer" "Health checks; afinidad WebSocket" "Nginx/LB gestionado"
            }
            deploymentNode "Zona privada" "VPC / red interna Docker" {
                deploymentNode "Nodos de aplicacion" {
                    deploymentNode "API Backend (Docker)" "Stateless" "Docker" 2 {
                        containerInstance api
                    }
                    deploymentNode "Worker de Reasignacion (Docker)" "Bulkhead" "Docker" 2 {
                        containerInstance workerReasign
                    }
                    deploymentNode "Worker de Inactividad (Docker)" "Lider unico" "Docker" {
                        containerInstance workerInactividad
                    }
                    deploymentNode "Consumers M4/M5 (Docker)" "Bulkhead; reintento/DLQ" "Docker" {
                        containerInstance consumers
                    }
                }
                deploymentNode "Datos y apoyo" {
                    deploymentNode "PostgreSQL primario" "Fuente de verdad" "postgres:15" {
                        containerInstance postgres
                    }
                    deploymentNode "PostgreSQL replica (standby)" "Streaming replication" "postgres:15" {
                        containerInstance postgres
                    }
                    deploymentNode "Backups" "WAL + pg_dump (PITR)" "Almacenamiento externo cifrado"
                    deploymentNode "Redis (AOF)" "Sesiones, cache, cola; AOF" "redis:7" {
                        containerInstance redis
                    }
                    deploymentNode "RabbitMQ + DLQ" "Colas duraderas" "rabbitmq:3" {
                        containerInstance rabbit
                    }
                }
            }
            gateway -> lb "Enruta tras terminar TLS"
        }
    }

    views {
        systemContext comedor "Contexto" {
            include *
            autolayout lr
        }
        container comedor "Contenedores" {
            include *
            autolayout lr
        }
        component api "Componentes_API" {
            include *
            autolayout lr
        }
        component workerReasign "Componentes_M6" {
            include *
            autolayout lr
        }
        component consumers "Componentes_M4_M5" {
            include *
            autolayout lr
        }
        deployment comedor produccion "Despliegue" {
            include *
            autolayout lr
        }

        styles {
            element "External" {
                background #999999
                color #ffffff
            }
            element "Database" {
                shape Cylinder
            }
            element "Message Broker" {
                shape Pipe
            }
        }
    }
}
```

## Nivel 1 — Contexto

Vista `Contexto` del workspace. Render disponible en [7.5.1. Diagrama de Contexto (C1)](../../../7/7.5/7.5.1/7.5.1.md).

| Actor / Sistema | Rol |
|---|---|
| Estudiante | Usa la app para autenticarse, encolarse, recibir notificaciones y seguir su turno |
| Administrador | Gestiona `turnos_config`, `turno_dia` y el menú (M7) |
| Sistema de Comedor UNI | Sistema documentado; orquesta cola, turnos, reasignación, notificaciones y configuración |
| Google Login / Intranet ORCE | Identidad institucional y datos del estudiante (scraping; no hay OAuth/API oficial) |
| Expo Push | Servicio externo de notificaciones push |
