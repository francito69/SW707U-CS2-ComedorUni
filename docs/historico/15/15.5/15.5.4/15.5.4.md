# 15.5.4. Despliegue

Vista `Despliegue` (entorno `Produccion`) del workspace consolidado definido en [15.5.1](../15.5.1/15.5.1.md). Es la **vista nueva** que asigna los contenedores a la infraestructura y evidencia las decisiones de la [Sección 2 — Estabilidad y Continuidad](../../../14/14.md).

---

## Vista de despliegue (Structurizr DSL)

```structurizr
# Pertenece al workspace consolidado de 15.5.1
deployment comedor produccion "Despliegue" {
    include *
    autolayout lr
}
```

El entorno `Produccion` (definido en 15.5.1) modela: zonas pública/borde/privada, gateway + load balancer, réplicas de API (`2`) y Worker de Reasignación (`2`), PostgreSQL primario + réplica standby + backups, Redis con AOF y RabbitMQ con DLQ.

---

## Documentación de respaldo por nodo

| Nodo | Tecnología | Propósito y responsabilidades | Despliegue (réplicas / recursos) | Zona / seguridad |
|---|---|---|---|---|
| API Gateway / Reverse Proxy | Nginx/Traefik | Termina TLS, rate limiting, autenticación de admin; oculta topología | 1+ (activo/standby) | Borde/DMZ; punto de cifrado |
| Load Balancer | Nginx/LB gestionado | Distribuye entre réplicas del API con health checks; afinidad WebSocket | Integrado/gestionado | Borde |
| API Backend | FastAPI (Docker) | Aloja M1/M2/M3/M5/M7; stateless | ≥ 2 réplicas | Privada |
| Worker de Reasignación | Python (Docker) | M6; consumo idempotente; aislado del API | ≥ 2 réplicas; `SKIP LOCKED` | Privada |
| Worker de Inactividad | Python (Docker) | M3; cancela turnos abandonados (heartbeat) | 1 (líder único, idempotente) | Privada |
| Consumers M4/M5 | Python aio-pika (Docker) | Notificación y seguimiento; reintento/DLQ | 1+ réplicas | Privada |
| PostgreSQL primario | postgres:15 | Fuente de verdad de todos los módulos; ACID | 1 primario; volumen persistente | Privada; TLS; sin acceso público |
| PostgreSQL réplica | postgres:15 (standby) | HA y descarga de lecturas; promovible | 1 standby (streaming) | Privada |
| Backups | WAL + `pg_dump` | Recuperación ante desastre (PITR) | Programados; externo cifrado | Privada/externa |
| Redis | redis:7 (AOF) | Sesiones (M1), cache config (M7), cola (M2); AOF | 1 (clúster a futuro) | Privada; TLS |
| RabbitMQ + DLQ | rabbitmq:3 | Eventos turno.* + reintentos | 1 (clúster a futuro); colas duraderas | Privada |
| Servicios externos | Google / ORCE / Expo | Identidad, datos y push | Gestionados por terceros | Acceso saliente HTTPS |

---

## Trazabilidad con la Sección 2 (estabilidad)

| Eje | Decisión visible en el despliegue | Soporta |
|---|---|---|
| Continuidad | PostgreSQL primario+réplica+backups; RabbitMQ+DLQ; Worker idempotente | Recuperación, prevención de pérdida y de cascada (14.5.1) |
| Escalabilidad/Rendimiento | Réplicas de API/Worker tras LB; Redis (cache/cola) con AOF | Escalado horizontal y baja latencia (14.5.2) |
| Seguridad | Gateway con TLS + authN admin; zonas pública/privada; datos sin exposición pública | Control de acceso y cifrado en tránsito (14.5.3) |
