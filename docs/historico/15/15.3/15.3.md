# 15.3. Módulo 3 / Integrante 3

**Módulos cubiertos:** M6 – Reasignación de Turnos · M7 – Configuración Operativa

Esta sección mantiene actualizados los tres niveles C4 (Contexto, Contenedores, Componentes) reflejando las decisiones de las secciones 1 (patrones/diseño) y 2 (estabilidad — ver [14.3](../../14/14.3/14.3.md)), y agrega el **diagrama de despliegue**. Los diagramas se definen como código **Structurizr DSL**; los renders ya disponibles de los niveles 1–3 están en la [Documentación de Arquitectura (sección 7)](../../7/7.md).

## Diagrama de Despliegue (nuevo)

<img src="../../../../resources/img/Nivel4_Despliegue_M6_M7.png">

### Documentación de respaldo por nodo

| Nodo | Tecnología | Propósito y responsabilidades | Despliegue (réplicas / recursos) | Zona / seguridad |
|---|---|---|---|---|
| API Gateway / Reverse Proxy | Nginx/Traefik | Termina TLS, aplica rate limiting y autenticación de admin antes de llegar al API; oculta la topología interna | 1+ (activo/standby) | Borde/DMZ; punto de cifrado (HTTPS→interno) |
| Load Balancer | Nginx/LB gestionado | Distribuye peticiones entre réplicas del API con health checks; saca de rotación instancias no sanas | Integrado al gateway o gestionado | Borde |
| API Backend | FastAPI (Docker) | Sirve M7 (config) y orquesta turnos; stateless para escalar horizontalmente | ≥ 2 réplicas (escalado horizontal) | Privada |
| Worker de Reasignación | Python (Docker) | Ejecuta M6 (`llamar_siguiente`) consumiendo de RabbitMQ; aislado del API (bulkhead) | ≥ 2 réplicas; `SKIP LOCKED` evita contención | Privada |
| PostgreSQL primario | postgres:15 | Fuente de verdad de `turnos`, `turno_dia`, `turnos_config`; transacciones ACID | 1 primario; volumen persistente | Privada; sin exposición pública; TLS |
| PostgreSQL réplica | postgres:15 (standby) | Alta disponibilidad y descarga de lecturas; promovible ante caída del primario | 1 standby por replicación streaming | Privada |
| Backups | WAL archiving + `pg_dump` | Recuperación ante desastre (PITR) | Programados; almacenamiento externo | Privada/externa cifrada |
| Redis | redis:7 (AOF) | Cache-Aside de `turnos_config` (M7); persistencia AOF como red de seguridad | 1 (o clúster/replica a futuro) | Privada; TLS |
| RabbitMQ + DLQ | rabbitmq:3 | Desacople de M6 y reintentos vía DLQ | 1 (clúster a futuro); colas duraderas | Privada |

> **Trazabilidad con Sección 2:** réplicas de API/Worker + LB → continuidad y escalabilidad horizontal (2.1/2.2); PostgreSQL primario+réplica+backups → recuperación y prevención de pérdida (2.1); Redis (Cache-Aside) y RabbitMQ+DLQ → rendimiento y reintento idempotente (2.2/2.1); gateway, zonas pública/privada y TLS → control de acceso y cifrado en tránsito (2.3).

## Actualización de ADRs

| ADR | Estado | Cambio |
|---|---|---|
| **ADR-15.3-M6-002 — Worker de reasignación como contenedor separable** | Nuevo | M6 se despliega como worker(s) independiente(s) del API (bulkhead), escalable horizontalmente y desacoplado por RabbitMQ. Soporta continuidad (2.1) y escalabilidad (2.2). |
| **ADR-15.3-SYS-001 — Alta disponibilidad de PostgreSQL** | Nuevo | Se adopta PostgreSQL primario + réplica standby (streaming) y backups WAL/dump para HA y recuperación. Complementa [ADR-9.3-M7-001](../../9/9.3/9.3.md). |
| **ADR-15.3-SYS-002 — Borde con gateway, zonas y TLS** | Nuevo | Separación de zona pública/privada con gateway (TLS termination, rate limiting, authN admin); datos sin exposición pública. Materializa las tácticas de 2.3. |
| [ADR-11.3 — Proxy/Cache-Aside (Redis) de M7](../../11/11.3/11.3.md) | Actualizado | Se confirma Redis como contenedor de apoyo en zona privada con AOF; invalidación dirigida desde el API. |
