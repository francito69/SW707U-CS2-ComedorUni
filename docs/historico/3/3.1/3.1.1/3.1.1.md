# 3.1.1. Módulo 1 / Integrante 1

**Módulos asignados**
- M1: Autenticación
- M4: Notificaciones
- M5: Seguimiento

## Módulo 1: Autenticación

El módulo de autenticación se encarga de validar la identidad y condición académica de los estudiantes que acceden al sistema de gestión de colas virtuales. Utiliza credenciales institucionales (@uni.pe) e integración con servicios externos de validación de identidad para garantizar que solo estudiantes activos puedan acceder.

Este módulo es el punto de entrada al sistema y es crítico para la seguridad, ya que asegura que cada sesión sea personal e intransferible. Además, mantiene el control de sesiones activas y permite el cierre seguro de la sesión del estudiante.

Su responsabilidad se centra en la validación de identidad y el control de acceso.

| ID      | Requisito Funcional                                                                                                                      | Actor(es) |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| RF-M1-01 | El sistema debe permitir que el estudiante ingrese sus credenciales institucionales (@uni.pe) para acceder.                               | Estudiante |
| RF-M1-02 | El sistema debe validar las credenciales del estudiante a través de un servicio externo de autenticación.                                | Sistema   |
| RF-M1-03 | El sistema debe verificar que el estudiante sea un estudiante activo consultando la información institucional.                            | Sistema   |
| RF-M1-04 | El sistema debe rechazar el acceso si el estudiante no es activo o sus credenciales son inválidas.                                       | Sistema   |
| RF-M1-05 | El sistema debe crear una sesión personal e intransferible para cada estudiante autenticado.                                              | Sistema   |
| RF-M1-06 | El sistema debe registrar el evento de autenticación con fecha, hora y resultado para auditoría.                                          | Sistema   |
| RF-M1-07 | El sistema debe permitir que el estudiante cierre su sesión de manera segura.                                                             | Estudiante |


## Casos de Uso
### CU01: Autenticar estudiante

| Campo       | Detalle                                                                                                   |
| ----------- | --------------------------------------------------------------------------------------------------------- |
| Nombre      | Autenticar estudiante                                                                                     |
| Actor       | Estudiante                                                                                                |
| Descripción | Permite que un estudiante inicie sesión en el sistema con sus credenciales institucionales.               |

<br>

**Flujo principal**
1. El estudiante accede a la página de autenticación.
2. Ingresa sus credenciales institucionales (@uni.pe).
3. El sistema valida las credenciales con el servicio externo.
4. El sistema verifica que el estudiante sea activo.
5. El sistema crea una sesión personal.
6. El estudiante accede al sistema.

**Flujos alternativos**
1. Las credenciales son inválidas → se rechaza el acceso.
2. El estudiante no es activo → se rechaza el acceso.
3. El servicio externo no responde → se muestra error y se intenta luego.

**Postcondiciones**
1. El estudiante tiene una sesión activa en el sistema.
2. Se registra el evento de autenticación.

**Excepciones**
1. Error en validación de credenciales.
2. Error en consulta de estado académico.


### CU02: Cerrar sesión

| Campo       | Detalle                                                                                                   |
| ----------- | --------------------------------------------------------------------------------------------------------- |
| Nombre      | Cerrar sesión                                                                                             |
| Actor       | Estudiante                                                                                                |
| Descripción | Permite que el estudiante cierre su sesión de manera segura.                                              |

**Flujo principal**
1. El estudiante solicita cerrar sesión.
2. El sistema invalida la sesión actual.
3. El sistema registra el evento de cierre de sesión.
4. El estudiante es redirigido a la página de autenticación.

**Flujos alternativos**
1. La sesión ya ha expirado → se redirige automáticamente.

**Postcondiciones**
1. La sesión está cerrada.
2. Se registra el evento en auditoría.

**Excepciones**
1. Error al invalidar la sesión.

## Módulo 4: Notificaciones

El módulo de notificaciones se encarga de mantener informado al estudiante sobre los eventos relevantes del proceso de gestión de colas y turnos. Envía notificaciones cuando se asigna un turno, cuando el turno está próximo a activarse, cuando debe confirmar su asistencia, o cuando su turno es liberado o reasignado.

Este módulo utiliza diferentes canales de comunicación (correo electrónico, notificaciones en la plataforma, SMS) para garantizar que el estudiante reciba la información de manera oportuna. Permite que el estudiante configure sus preferencias de notificación según su disponibilidad.

Su responsabilidad se centra en la comunicación de eventos del sistema al estudiante.

| ID      | Requisito Funcional                                                                                                                      | Actor(es) |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| RF-M4-01 | El sistema debe enviar notificación cuando se asigna un turno al estudiante.                                                              | Sistema   |
| RF-M4-02 | El sistema debe enviar notificación cuando el turno del estudiante está próximo a activarse.                                             | Sistema   |
| RF-M4-03 | El sistema debe enviar notificación solicitando confirmación de asistencia cuando el turno se activa.                                    | Sistema   |
| RF-M4-04 | El sistema debe enviar notificación informando cuando el turno es liberado por inasistencia.                                             | Sistema   |
| RF-M4-05 | El sistema debe enviar notificación cuando el turno es reasignado a otro estudiante.                                                     | Sistema   |
| RF-M4-06 | El sistema debe enviar notificación de confirmación exitosa de asistencia.                                                                | Sistema   |
| RF-M4-07 | El sistema debe permitir que el estudiante configure sus preferencias de notificación.                                                   | Estudiante |
| RF-M4-08 | El sistema debe registrar todas las notificaciones enviadas para auditoría.                                                               | Sistema   |


## Casos de Uso
### CU01: Notificar asignación de turno

| Campo       | Detalle                                                                                                   |
| ----------- | --------------------------------------------------------------------------------------------------------- |
| Nombre      | Notificar asignación de turno                                                                             |
| Actor       | Sistema                                                                                                   |
| Descripción | El sistema notifica al estudiante cuando un turno le ha sido asignado.                                    |

<br>

**Flujo principal**
1. Se asigna un turno a un estudiante.
2. El sistema prepara la notificación con los detalles del turno.
3. El sistema envía la notificación por los canales configurados.
4. Se registra el envío en el historial de notificaciones.

**Flujos alternativos**
1. El estudiante no tiene canales activos → se guarda la notificación como pendiente.

**Postcondiciones**
1. El estudiante recibe la notificación.
2. Se registra en el historial.

**Excepciones**
1. Error al enviar la notificación.
2. Fallos en el canal de comunicación.


### CU02: Notificar confirmación requerida

| Campo       | Detalle                                                                                                   |
| ----------- | --------------------------------------------------------------------------------------------------------- |
| Nombre      | Notificar confirmación de asistencia requerida                                                             |
| Actor       | Sistema                                                                                                   |
| Descripción | El sistema notifica al estudiante que debe confirmar su asistencia antes de que expire el tiempo límite.   |

**Flujo principal**
1. El turno del estudiante se activa.
2. El sistema envía notificación solicitando confirmación.
3. Se especifica el tiempo límite de confirmación.
4. Se registra el envío de notificación.

**Flujos alternativos**
1. El estudiante ya confirmo → se cancela la notificación.

**Postcondiciones**
1. El estudiante recibe la notificación de confirmación.
2. Se registra el evento.

**Excepciones**
1. Error al enviar la notificación.


### CU03: Configurar preferencias de notificación

| Campo       | Detalle                                                                                                   |
| ----------- | --------------------------------------------------------------------------------------------------------- |
| Nombre      | Configurar preferencias de notificación                                                                   |
| Actor       | Estudiante                                                                                                |
| Descripción | Permite que el estudiante seleccione los canales y tipos de notificación que desea recibir.               |

**Flujo principal**
1. El estudiante accede a configuración de preferencias.
2. Selecciona los canales de notificación (correo, SMS, plataforma).
3. Selecciona qué tipos de eventos desea ser notificado.
4. El sistema guarda las preferencias.

**Flujos alternativos**
1. El estudiante desactiva todas las notificaciones → se mantiene el registro de eventos.

**Postcondiciones**
1. Las preferencias están configuradas.
2. Las futuras notificaciones respetan estas preferencias.

**Excepciones**
1. Error al guardar las preferencias.

## Módulo 5: Seguimiento

El módulo de seguimiento se encarga de proporcionar al estudiante y al sistema información en tiempo real sobre el estado de sus turnos, posición en la cola, historial de actividades y trazabilidad de cambios. Permite que el estudiante consulte en cualquier momento el estado actual de su turno y el historial de solicitudes previas.

Este módulo también registra todos los eventos relevantes del proceso (asignación, confirmación, reasignación, liberación) para fines de auditoría, seguimiento y resolución de conflictos. Centraliza la información histórica del sistema.

Su responsabilidad se centra en la recopilación, organización y visualización de información histórica y de estado, sin interferir con los procesos transaccionales del sistema.

| ID      | Requisito Funcional                                                                                                                      | Actor(es) |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| RF-M5-01 | El sistema debe permitir que el estudiante consulte el estado actual de su turno activo.                                                  | Estudiante |
| RF-M5-02 | El sistema debe mostrar la posición del estudiante en la cola virtual si está en espera.                                                  | Sistema   |
| RF-M5-03 | El sistema debe permitir consultar el historial de turnos solicitud, asignación, confirmación).                                          | Estudiante |
| RF-M5-04 | El sistema debe registrar todos los eventos del proceso con timestamp, actor y descripción.                                              | Sistema   |
| RF-M5-05 | El sistema debe mantener un registro de cambios de estado para cada turno (auditoría).                                                   | Sistema   |
| RF-M5-06 | El sistema debe permitir que personal autorizado consulte el historial completo de actividades de cualquier estudiante.                 | Personal  |
| RF-M5-07 | El sistema debe generar reportes de seguimiento para análisis administrativo.                                                             | Sistema   |
| RF-M5-08 | El sistema debe garantizar la trazabilidad completa de todas las acciones realizadas en el sistema.                                      | Sistema   |


## Casos de Uso
### CU01: Consultar estado del turno

| Campo       | Detalle                                                                                                   |
| ----------- | --------------------------------------------------------------------------------------------------------- |
| Nombre      | Consultar estado del turno                                                                                |
| Actor       | Estudiante                                                                                                |
| Descripción | Permite que el estudiante verifique en tiempo real el estado de su turno actual.                          |

<br>

**Flujo principal**
1. El estudiante accede a la sección de estado de turno.
2. El sistema obtiene el turno activo o próximo.
3. Muestra el estado, horario, bloque de tiempo y acciones disponibles.
4. El estudiante puede confirmar o desistir según el estado.

**Flujos alternativos**
1. El estudiante no tiene turno activo → se muestra posición en cola.
2. El turno está expirado → se muestra que fue liberado.

**Postcondiciones**
1. El estudiante visualiza su estado actual.
2. Se registra la consulta.

**Excepciones**
1. Error al recuperar el estado del turno.


### CU02: Consultar posición en cola

| Campo       | Detalle                                                                                                   |
| ----------- | --------------------------------------------------------------------------------------------------------- |
| Nombre      | Consultar posición en cola                                                                                |
| Actor       | Estudiante                                                                                                |
| Descripción | Permite que el estudiante vea su posición actual en la cola virtual.                                      |

**Flujo principal**
1. El estudiante accede a la sección de cola.
2. Si está en espera, se muestra su posición exacta.
3. Se muestra cuántos estudiantes están antes y después.
4. Se estima cuándo será su turno.

**Flujos alternativos**
1. El estudiante no está en cola → se indica que no tiene solicitud pendiente.

**Postcondiciones**
1. El estudiante conoce su posición.
2. Se registra la consulta.

**Excepciones**
1. Error al calcular la posición.


### CU03: Consultar historial de turnos

| Campo       | Detalle                                                                                                   |
| ----------- | --------------------------------------------------------------------------------------------------------- |
| Nombre      | Consultar historial de turnos                                                                             |
| Actor       | Estudiante                                                                                                |
| Descripción | Permite que el estudiante vea el historial de todos sus turnos solicitados, asignados y realizados.       |

**Flujo principal**
1. El estudiante accede a historial de turnos.
2. El sistema muestra todos los turnos (pasados y presentes) con:
   - Fecha de solicitud
   - Hora asignada
   - Estado (confirmado, no confirmado, realizado)
   - Bloque de tiempo
3. El estudiante puede ver detalles de cada turno.

**Flujos alternativos**
1. El estudiante no tiene historial → se muestra mensaje informativo.

**Postcondiciones**
1. El estudiante visualiza su historial completo.
2. Se registra la consulta.

**Excepciones**
1. Error al recuperar el historial.


### CU04: Registrar evento para auditoría

| Campo       | Detalle                                                                                                   |
| ----------- | --------------------------------------------------------------------------------------------------------- |
| Nombre      | Registrar evento para auditoría                                                                            |
| Actor       | Sistema                                                                                                   |
| Descripción | El sistema registra automáticamente todos los eventos relevantes con información completa de trazabilidad. |

**Flujo principal**
1. Ocurre un evento en el sistema (asignación, confirmación, etc).
2. El sistema registra: timestamp, tipo de evento, actor, estudiante afectado.
3. El evento se almacena en el historial de auditoría.

**Flujos alternativos**
1. No aplica.

**Postcondiciones**
1. El evento está registrado en auditoría.
2. Es consultable por personal autorizado.

**Excepciones**
1. Error al guardar el registro de auditoría.
