# 3.2.3. Módulo 3 / Integrante 3

# Módulo de Reasignación de Turnos

En el módulo de reasignación de turnos se han identificado atributos de calidad prioritarios para asegurar que los cupos liberados por inasistencia se reasignen de forma automática, ordenada y sin afectar la integridad de la cola virtual.

El atributo más importante en este módulo es **Confiabilidad**, debido a que cada liberación de turno debe desencadenar una reasignación correcta al siguiente estudiante elegible, respetando estrictamente el orden de prioridad; cualquier inconsistencia invalida el proceso completo.

También se prioriza **Disponibilidad**, porque la reasignación automática debe ejecutarse durante toda la ventana de atención, recuperarse de fallos transitivos sin pérdida de eventos, y mantener sincronización entre cola y estado de turnos.

Otro atributo relevante es **Rendimiento**, ya que la reasignación debe ejecutarse en tiempos cortos para evitar cupos ociosos y mantener la continuidad del proceso de atención en horas de alta demanda.

| Múltiples expiraciones          | Múltiples turnos expiran en paralelo                                      | El sistema asigna cada cupo exactamente una sola vez sin duplicidad                       | 0 duplicidad de cupos reasignados; atomicidad garantizada                      |

| Incremento de estudiantes  | Aumento progresivo de estudiantes en espera durante semestre    | El sistema mantiene la reasignación automática sin fallos acumulativos        | 100% de reasignaciones completadas correctamente bajo carga creciente        |

# Módulo de Configuración del Sistema

En el módulo de configuración del sistema se han identificado atributos de calidad prioritarios que garantizan una administración confiable de parámetros críticos, como horarios, bloques de tiempo, capacidad por turno y tiempo máximo de confirmación.

El atributo más importante en este módulo es **Seguridad**, porque solo personal autorizado debe poder modificar la configuración operacional del sistema; acceso no controlado podría dejar el sistema en estado incoherente.

También se prioriza **Confiabilidad**, ya que los parámetros configurados deben aplicarse de manera consistente y sin conflictos, evitando impactos negativos en la asignación y reasignación de turnos.

Otro atributo relevante es **Usabilidad**, dado que los administradores deben comprender claramente la interfaz de configuración y no cometer errores al parametrizar horarios, bloques o capacidades.

## Escenarios de calidad - M7 Configuración del Sistema

### Seguridad
| Fuente del Estímulo      | Estímulo                                                               | Respuesta                                                                  | Medida de Respuesta                                                       |
| ------------------------ | ---------------------------------------------------------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| Usuario sin permisos     | Intento de modificar parámetros de configuración                        | El sistema deniega el acceso y registra el intento                         | 100% de intentos no autorizados rechazados                                |
| Administrador autorizado | Actualización válida de parámetros                                      | El sistema permite cambios con control de autenticación y autorización      | 100% de cambios válidos ejecutados por rol autorizado                     |
| Auditoría de cambios     | Revisión de historial de configuraciones                                | El sistema conserva bitácora de usuario, fecha, hora y detalle del cambio  | 100% de cambios con trazabilidad completa                                 |

### Confiabilidad

| ------------------------------ | ------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Validación de parámetros       | Ingreso de valores incompatibles (horarios cruzados, capacidad inválida) | El sistema detecta conflictos, rechaza configuración inválida y solicita corrección     | 0 configuraciones inválidas aplicadas                                   |
| Sistema en operación           | Aplicación de configuraciones durante operación activa                    | El sistema mantiene consistencia entre configuración guardada y configuración activa     | 100% de coherencia entre parámetros persistidos y parámetros en uso      |
| Recuperación ante error        | Fallo durante actualización de configuración                               | El sistema evita corrupción y mantiene la última configuración válida                    | 0 pérdida de configuración válida                                        |

### Usabilidad
| Fuente del Estímulo        | Estímulo                                                                 | Respuesta                                                                        | Medida de Respuesta                                                        |
| -------------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |

| Configuración compleja     | Parametrización de múltiples bloques, horarios y capacidades simultáneamente | La interfaz organiza opciones de forma lógica con validación en tiempo real | Validación inmediata de conflictos; sugerencias de valores correctos      |
| Recuperación de error      | Administrador comete error al ingresar capacidad o horario               | El sistema proporciona mensaje claro, indica el error exacto y sugiere corrección | Tiempo para corregir < 30 segundos; interfaz amigable para correción      |
