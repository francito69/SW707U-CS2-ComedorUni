# 3.2.5. Listado Consolidado

## M1 — Módulo de Autenticación

**Propósito**: Validar la identidad y condición académica de estudiantes, garantizando acceso seguro y sesiones personales.

### Atributos de Calidad Críticos

- **Seguridad**: Control de acceso institucional, rechazo de intentos no autorizados, auditoría de eventos
- **Disponibilidad**: Operación continua sin pérdida de estado, recuperación de fallos transitivos
- **Rendimiento**: Autenticación rápida incluso en picos de demanda

### Escenarios de Operación

| Escenario | Atributo | Situación | Resultado Esperado | Métrica |
|-----------|----------|-----------|-------------------|---------|
| Acceso con credenciales válidas | Seguridad | Estudiante ingresa @uni.pe y contraseña | Sistema valida y crea sesión personal | 100% de accesos autorizados habilitados |
| Rechazo de credenciales inválidas | Seguridad | Intento con dominio externo o credenciales falsas | Sistema rechaza inmediatamente y registra intento | 100% de intentos bloqueados |
| Sesión duplicada | Seguridad | Mismo usuario intenta iniciar sesión desde otro dispositivo | Sistema invalida sesión anterior o rechaza nueva | 0 sesiones duplicadas reutilizables |
| Operación durante fallo externo | Disponibilidad | Servicio de validación externo temporal inoperativo | Sistema maneja error sin autorizar accesos indebidos | Recuperación < 5s; 0 accesos sin validación |
| Múltiples sesiones activas | Disponibilidad | Gestión de muchas sesiones simultáneamente | Sistema mantiene estado consistente de todas | 100% de sesiones gestionadas |
| Autenticación en hora pico | Rendimiento | Cientos de login simultáneos | Sistema procesa sin retraso significativo | < 2s por autenticación; latencia < 3s pico |
| Cierre seguro de sesión | Rendimiento | Estudiante solicita cerrar sesión | Sistema invalida inmediatamente | < 1s de cierre |

## M2 — Módulo de Gestión de Colas

**Propósito**: Administrar la estructura de colas virtuales, mantener orden FIFO y control de capacidad.

### Atributos de Calidad Críticos

- **Escalabilidad**: Manejo de ingreso simultáneo masivo sin perder orden ni datos
- **Confiabilidad**: Mantener consistencia FIFO, evitar duplicidad de registros
- **Seguridad**: Validar identidad antes de permitir ingreso a cola

### Escenarios de Operación

| Escenario | Atributo | Situación | Resultado Esperado | Métrica |
|-----------|----------|-----------|-------------------|---------|
| Ingreso masivo al inicio de horario | Escalabilidad | Múltiples estudiantes solicitan ingreso simultáneamente | Sistema procesa todos sin pérdida ni reordenamiento | Sin pérdida; degradación < 5% |
| Apertura de almuerzo y cena | Escalabilidad | Colas independientes simultáneas (almuerzo + cena) | Sistema gestiona ambas sin interferencia | 100% operativo en ambas colas |
| Crecimiento progresivo de usuarios | Escalabilidad | Incremento de estudiantes durante el semestre | Sistema mantiene función sin rediseño | Crecimiento sostenido sin caída |
| Verificación de orden FIFO | Confiabilidad | Estudiantes en espera verifican su posición | Orden respetado exactamente | 0% inconsistencias de posición |
| Intento de ingreso duplicado | Confiabilidad | Mismo estudiante intenta registrarse dos veces | Sistema detecta y rechaza duplicado | 0 duplicados en cola |
| Ingreso de estudiante no validado | Seguridad | Usuario sin autenticación intenta entrar a cola | Sistema bloquea ingreso | 100% rechazados sin validación |
| Actualización de posición en tiempo real | Rendimiento | Cambios frecuentes en cola (ingresos/salidas) | Posiciones actualizadas sin demora | < 2s de ingreso; latencia < 3s pico |

## M3 — Módulo de Gestión de Turnos

**Propósito**: Crear, asignar y controlar el ciclo de vida de turnos individuales.

### Atributos de Calidad Críticos

- **Confiabilidad**: Mantener consistencia de estados (asignado, activo, confirmado, expirado)
- **Rendimiento**: Generación y confirmación rápida, sin retrasos críticos
- **Seguridad**: Confirmación restringida solo al propietario del turno

### Escenarios de Operación

| Escenario | Atributo | Situación | Resultado Esperado | Métrica |
|-----------|----------|-----------|-------------------|---------|
| Ciclo completo del turno | Confiabilidad | Turno: generado → asignado → activado → confirmado → completado | Todos los estados consistentes y auditables | 0% inconsistencias de estado |
| Generación concurrente de turnos | Confiabilidad | Múltiples turnos asignados simultáneamente | Cada turno único, sin duplicación | 0 duplicidad de turnos |
| Expiración sin confirmación | Confiabilidad | Estudiante no confirma dentro del tiempo límite | Turno marcado como expirado, cupo liberado | 100% de expiraciones registradas |
| Confirmación no autorizada | Seguridad | Estudiante intenta confirmar turno de otro | Sistema rechaza operación | 100% de intentos bloqueados |
| Confirmación en horario pico | Rendimiento | Confirmación durante alta demanda | Sistema procesa sin demora | < 2s de confirmación |
| Generación en hora pico | Rendimiento | Asignación simultánea de cientos de turnos | Procesamiento en paralelo sin cuello de botella | < 2s de generación |

## M4 — Módulo de Notificaciones

**Propósito**: Comunicar eventos críticos del turno (asignación, confirmación, liberación, reasignación).

### Atributos de Calidad Críticos

- **Rendimiento**: Entrega rápida de alertas críticas para evitar pérdida de turno
- **Disponibilidad**: Operación continua sin pérdida de mensajes
- **Seguridad**: Restricción de acceso por usuario, auditoría de envíos

### Escenarios de Operación

| Escenario | Atributo | Situación | Resultado Esperado | Métrica |
|-----------|----------|-----------|-------------------|---------|
| Notificación de asignación | Rendimiento | Turno asignado al estudiante | Notificación enviada inmediatamente | < 2s de latencia |
| Alerta de confirmación requerida | Rendimiento | Ventana de confirmación está abierta | Notificación prioritaria sin demoras | < 2s de envío |
| Envío masivo en hora pico | Rendimiento | Cientos de notificaciones simultáneas | Sistema mantiene latencia estable | < 3s promedio en pico |
| Fallo del canal de envío | Disponibilidad | Error temporal en canal primario | Sistema registra, reintenta, conserva trazabilidad | 0 pérdida de registro; disponibilidad >= 99% |
| Envíos sin pérdida durante carga | Disponibilidad | Alta concurrencia de mensajes | Sistema procesa todos sin descartar | Tasa entrega >= 99% |
| Acceso a notificaciones de otro | Seguridad | Estudiante intenta ver mensajes ajenos | Sistema bloquea acceso | 100% de accesos bloqueados |
| Modificación de preferencias no autorizada | Seguridad | Intento de cambiar preferencias de otro | Sistema rechaza cambio | 100% de cambios validados por autorización |

## M5 — Módulo de Seguimiento

**Propósito**: Proporcionar visibilidad en tiempo real de estado, posición e historial de turno.

### Atributos de Calidad Críticos

- **Disponibilidad**: Información siempre accesible durante operación, sin pérdida de historial
- **Rendimiento**: Consultas rápidas de estado y posición
- **Usabilidad**: Presentación clara e intuitiva de información

### Escenarios de Operación

| Escenario | Atributo | Situación | Resultado Esperado | Métrica |
|-----------|----------|-----------|-------------------|---------|
| Consulta de estado en operación | Disponibilidad | Estudiante verifica turno en cualquier momento | Información actualizada disponible | >= 99.5% disponibilidad |
| Consulta de posición en cola | Rendimiento | Estudiante quiere saber dónde está en fila | Posición calculada y mostrada sin demora | < 2s |
| Consulta de historial | Rendimiento | Revisión de eventos pasados (asignación, confirmación, etc) | Historial completo en tiempo corto | < 3s para historial reciente |
| Recuperación de fallo transitorio | Disponibilidad | Error temporal al recuperar datos | Sistema reintenta sin perder historial | Recuperación < 5s; 0 pérdida datos |
| Consultas concurrentes en pico | Disponibilidad | Cientos de estudiantes consultando simultáneamente | Sistema responde a todos sin degradación | Degradación < 5%; consistencia 100% |
| Comprensión de interfaz por primer uso | Usabilidad | Estudiante accede a seguimiento por primera vez | Entiende estado y posición sin instrucción | 100% comprensión inmediata |
| Visualización clara de eventos | Usabilidad | Historial presentado al estudiante | Eventos organizados cronológicamente y legibles | 100% de eventos accesibles |
| Acceso a historial de otro | Seguridad | Intento de ver información de otro estudiante | Sistema bloquea acceso | 100% de consultas no autorizadas rechazadas |

## M6 — Módulo de Reasignación de Turnos

**Propósito**: Liberar y reasignar automáticamente cupos no confirmados, respetando orden FIFO.

### Atributos de Calidad Críticos

- **Confiabilidad**: Mantener integridad en flujo liberar → reasignar → notificar
- **Disponibilidad**: Operación continua, recuperación sin pérdida de eventos
- **Rendimiento**: Reasignación rápida para evitar cupos ociosos

### Escenarios de Operación

| Escenario | Atributo | Situación | Resultado Esperado | Métrica |
|-----------|----------|-----------|-------------------|---------|
| Ciclo completo de reasignación | Confiabilidad | Liberación → búsqueda en fila → asignación al siguiente | Todos los pasos consistentes, sin duplicidad | 0% inconsistencias; atomicidad 100% |
| Múltiples expiraciones paralelas | Confiabilidad | Varios turnos expiran simultáneamente | Cada cupo reasignado exactamente una vez | 0 duplicidad de asignaciones |
| Recuperación de fallo en reasignación | Confiabilidad | Error durante proceso de reasignación | Sistema recupera y completa sin perder evento | 0 pérdida; recuperación < 5s |
| Operación continua sin detención | Disponibilidad | Reasignaciones durante toda ventana de atención | Sistema mantiene estabilidad | >= 99.5% disponibilidad |
| Crecimiento de estudiantes en fila | Disponibilidad | Más estudiantes en espera conforme avanza semestre | Sistema mantiene reasignación sin fallos | 100% completadas correctamente |
| Recuperación ante fallo de nodo | Disponibilidad | Nodo o proceso de reasignación falla | Sistema reasigna sin pérdida de información | Recuperación automática sin intervención |
| Reasignación en tiempo corto | Rendimiento | Cupo liberado debe reasignarse sin demora | Sistema asigna al siguiente sin retraso | < 3s de reasignación |
| Procesamiento de múltiples reasignaciones | Rendimiento | Muchos turnos vencen en misma franja | Sistema procesa todas en paralelo | < 5s para múltiples reasignaciones |

## M7 — Módulo de Configuración del Sistema

**Propósito**: Permitir al administrador parametrizar horarios, bloques, capacidad y confirmación.

### Atributos de Calidad Críticos

- **Seguridad**: Solo admin puede modificar, auditoría de cambios obligatoria
- **Confiabilidad**: Configuración consistente, sin conflictos, coherencia garantizada
- **Usabilidad**: Interfaz clara para evitar errores de parametrización

### Escenarios de Operación

| Escenario | Atributo | Situación | Resultado Esperado | Métrica |
|-----------|----------|-----------|-------------------|---------|
| Intento de modificación no autorizado | Seguridad | Usuario sin permisos intenta cambiar parámetros | Sistema deniega y registra intento | 100% intentos bloqueados |
| Cambio válido por admin | Seguridad | Admin autorizado modifica configuración | Sistema permite y registra cambio con detalles | 100% de cambios auditables |
| Revisión de historial de cambios | Seguridad | Admin consulta quién cambió qué y cuándo | Sistema muestra bitácora completa | 100% trazabilidad |
| Validación de parámetros incompatibles | Confiabilidad | Admin ingresa horarios cruzados o capacidad inválida | Sistema detecta conflicto y rechaza | 0 configuraciones inválidas aplicadas |
| Aplicación durante operación activa | Confiabilidad | Cambio de configuración mientras sistema está en uso | Nueva config se aplica a nuevas solicitudes sin afectar vigentes | 100% coherencia; consistencia garantizada |
| Recuperación ante error de actualización | Confiabilidad | Fallo durante guardado de configuración | Sistema evita corrupción, mantiene última config válida | 0 pérdida de datos |
| Primer uso de panel de administración | Usabilidad | Admin nuevo accede a configuración | Interfaz claramente organizada y autoexplicativa | 100% comprensión sin instrucción |
| Parametrización compleja | Usabilidad | Admin debe configurar múltiples bloques, horarios y capacidades | Interfaz guía con validación inmediata y sugerencias | Validación en tiempo real |
| Corrección de error de parametrización | Usabilidad | Admin comete error al ingresar datos | Sistema proporciona mensaje claro e indica cómo corregir | < 30s para corregir; interfaz amigable |
