# 3.1.3. Módulo 3 / Integrante 3

**Módulos asignados**
- M6: Reasignación de turnos
- M7: Configuración del sistema

## Módulo 6: Reasignación de turnos

El módulo de reasignación de turnos se encarga de gestionar la asignación automática de cupos liberados cuando un estudiante no confirma su asistencia dentro del tiempo establecido. Cuando un turno es liberado por inasistencia, este módulo busca el próximo estudiante en espera dentro de la cola virtual y le asigna automáticamente el cupo disponible.

Su función principal es mantener la eficiencia del sistema asignando turnos liberados a estudiantes que se encuentran en la cola virtual, respetando el orden de prioridad establecido por las reglas de negocio. También registra todas las reasignaciones ocurridas para auditoría y seguimiento del sistema.

| ID      | Requisito Funcional                                                                                                                      | Actor(es) |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| RF-M6-01 | El sistema debe detectar automáticamente cuando un turno es liberado por falta de confirmación del estudiante.                           | Sistema   |
| RF-M6-02 | El sistema debe identificar el próximo estudiante en espera dentro de la cola virtual después de una liberación de cupo.                | Sistema   |
| RF-M6-03 | El sistema debe respetar el orden de prioridad establecido al reasignar turnos a estudiantes en espera.                                  | Sistema   |
| RF-M6-04 | El sistema debe asignar automáticamente el turno liberado al estudiante en espera seleccionado.                                          | Sistema   |
| RF-M6-05 | El sistema debe notificar al estudiante reasignado sobre su nuevo turno asignado.                                                        | Sistema   |
| RF-M6-06 | El sistema debe registrar todas las reasignaciones realizadas con información del turno original, liberado y reasignado.                | Sistema   |
| RF-M6-07 | El sistema debe mantener la integridad de la cola virtual durante el proceso de reasignación.                                           | Sistema   |


## Casos de Uso
### CU01: Liberar turno por inasistencia

| Campo       | Detalle                                                                                                   |
| ----------- | --------------------------------------------------------------------------------------------------------- |
| Nombre      | Liberar turno por inasistencia                                                                            |
| Actor       | Sistema                                                                                                   |
| Descripción | El sistema libera automáticamente el turno cuando el estudiante no confirma su asistencia en el tiempo establecido. |

<br>

**Flujo principal**
1. El sistema detecta que el tiempo de confirmación ha expirado.
2. El sistema marca el turno como no confirmado.
3. El sistema libera el cupo asociado al turno.
4. El sistema inicia el proceso de reasignación.

**Flujos alternativos**
1. El estudiante confirma a tiempo → no se libera el turno.

**Postcondiciones**
1. El turno está marcado como no confirmado.
2. El cupo está disponible para reasignación.

**Excepciones**
1. Error al actualizar el estado del turno.


### CU02: Reasignar turno a estudiante en espera

| Campo       | Detalle                                                                                                   |
| ----------- | --------------------------------------------------------------------------------------------------------- |
| Nombre      | Reasignar turno a estudiante en espera                                                                    |
| Actor       | Sistema                                                                                                   |
| Descripción | El sistema reasigna automáticamente el cupo liberado al próximo estudiante en espera en la cola virtual.   |

**Flujo principal**
1. Se detecta un cupo liberado.
2. El sistema identifica al próximo estudiante en espera.
3. El sistema valida que siga siendo elegible para la reasignación.
4. El sistema asigna el cupo al estudiante.
5. El sistema notifica al estudiante sobre su nuevo turno.
6. El sistema registra la reasignación.

**Flujos alternativos**
1. No hay estudiantes en espera → el cupo permanece disponible.
2. El estudiante en espera ya no es elegible → se continúa con el siguiente.

**Postcondiciones**
1. El estudiante tiene un nuevo turno asignado.
2. La reasignación queda registrada en el historial.

**Excepciones**
1. Error al identificar estudiantes en espera.
2. Fallo en la notificación al estudiante.

## Módulo 7: Configuración del sistema

El módulo de configuración del sistema se encarga de definir y mantener todos los parámetros operacionales que rigen el funcionamiento de la gestión de colas virtuales del comedor. Esto incluye la definición de horarios disponibles para cada servicio (almuerzo, cena), bloques de tiempo, capacidad máxima de cupos por turno, períodos de disponibilidad para solicitudes de turnos, y tiempos límite de confirmación.

Este módulo permite que personal administrativo autorizado configure el sistema según las necesidades institucionales sin requerir cambios en el código fuente. Centraliza la administración de parámetros y facilita la auditoría de todas las modificaciones realizadas en la configuración del sistema.

Su responsabilidad se centra únicamente en la gestión de parámetros de configuración, sin interferir con la lógica de asignación de turnos, reasignación o gestión de colas. Todos los cambios de configuración se aplican inmediatamente a nuevas solicitudes sin afectar turnos ya asignados.

| ID      | Requisito Funcional                                                                                                                      | Actor(es)     |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------- |
| RF-M7-01 | El sistema debe permitir configurar los horarios disponibles para cada tipo de servicio (almuerzo, cena).                               | Administrador |
| RF-M7-02 | El sistema debe permitir definir los bloques de tiempo y la duración de cada turno.                                                      | Administrador |
| RF-M7-03 | El sistema debe permitir definir la capacidad máxima de estudiantes por turno.                                                           | Administrador |
| RF-M7-04 | El sistema debe permitir establecer los períodos de tiempo durante los cuales los estudiantes pueden solicitar turnos.                   | Administrador |
| RF-M7-05 | El sistema debe permitir configurar el tiempo máximo de confirmación de asistencia.                                                      | Administrador |
| RF-M7-06 | El sistema debe validar que todos los parámetros ingresados sean coherentes, viables y no generen conflictos.                           | Sistema       |
| RF-M7-07 | El sistema debe registrar todas las modificaciones de configuración con fecha, hora, usuario y descripción del cambio realizado.        | Sistema       |
| RF-M7-08 | El sistema debe aplicar los cambios de configuración de forma inmediata a nuevas solicitudes sin afectar turnos ya asignados.          | Sistema       |


## Casos de Uso
### CU01: Configurar horarios y bloques de tiempo

| Campo       | Detalle                                                                                                   |
| ----------- | --------------------------------------------------------------------------------------------------------- |
| Nombre      | Configurar horarios y bloques de tiempo                                                                   |
| Actor       | Administrador                                                                                             |
| Descripción | Permite al administrador definir los horarios disponibles y los bloques de tiempo para cada servicio.     |

<br>

**Flujo principal**
1. El administrador accede a la sección de configuración de horarios.
2. Define los horarios disponibles para almuerzo y cena.
3. Establece los bloques de tiempo y duración de cada turno.
4. El sistema valida que no haya conflictos entre bloques.
5. El sistema guarda la configuración.
6. Se registra el cambio en el historial.

**Flujos alternativos**
1. Los horarios tienen conflictos → se solicita corrección.
2. La duración excede límites permitidos → se rechaza.

**Postcondiciones**
1. Los horarios y bloques quedan disponibles para nuevas solicitudes.
2. Se registra en el historial de cambios.

**Excepciones**
1. Error en la validación de horarios.
2. Fallo al guardar la configuración.


### CU02: Configurar capacidad por turno

| Campo       | Detalle                                                                                                   |
| ----------- | --------------------------------------------------------------------------------------------------------- |
| Nombre      | Configurar capacidad máxima por turno                                                                     |
| Actor       | Administrador                                                                                             |
| Descripción | Permite al administrador definir cuántos estudiantes máximo pueden tener un turno en cada bloque de tiempo.|

**Flujo principal**
1. El administrador ingresa la capacidad máxima por turno.
2. El sistema valida que sea un valor viable.
3. El sistema guarda la configuración.
4. Se aplica a nuevas solicitudes de turno.
5. Se registra el cambio.

**Flujos alternativos**
1. El valor es inválido o negativo → se rechaza.

**Postcondiciones**
1. La capacidad se actualiza en el sistema.
2. Se registra en el historial de cambios.

**Excepciones**
1. Error en la validación del parámetro.


### CU03: Configurar períodos de solicitud

| Campo       | Detalle                                                                                                   |
| ----------- | --------------------------------------------------------------------------------------------------------- |
| Nombre      | Configurar períodos de solicitud                                                                          |
| Actor       | Administrador                                                                                             |
| Descripción | Permite al administrador definir cuándo los estudiantes pueden realizar solicitudes de turnos.            |

**Flujo principal**
1. El administrador define las fechas y horarios en los que se abren solicitudes.
2. El sistema valida que los períodos sean válidos.
3. El sistema guarda la configuración.
4. El sistema habilita/deshabilita solicitudes según lo configurado.
5. Se registra el cambio.

**Flujos alternativos**
1. Los períodos tienen conflictos → se solicita corrección.

**Postcondiciones**
1. Los períodos quedan activos en el sistema.
2. Se registra en el historial de cambios.

**Excepciones**
1. Error en la validación de períodos.


### CU04: Configurar tiempo de confirmación

| Campo       | Detalle                                                                                                   |
| ----------- | --------------------------------------------------------------------------------------------------------- |
| Nombre      | Configurar tiempo máximo de confirmación                                                                  |
| Actor       | Administrador                                                                                             |
| Descripción | Permite al administrador definir el tiempo máximo que tiene un estudiante para confirmar su asistencia.   |

**Flujo principal**
1. El administrador define el tiempo máximo de confirmación (en minutos).
2. El sistema valida que sea un valor viable y coherente.
3. El sistema guarda la configuración.
4. Se aplica a nuevos turnos asignados.
5. Se registra el cambio.

**Flujos alternativos**
1. El valor es muy bajo o muy alto → se solicita confirmación.

**Postcondiciones**
1. El tiempo de confirmación se actualiza.
2. Se registra en el historial de cambios.

**Excepciones**
1. Error en la validación del parámetro.
