## Descripción de contenedores

| Contenedor | Tecnología | Responsabilidad | Módulos | Decisión de Sec. 2 que evidencia |
|---|---|---|---|---|
| App Móvil | React Native | Login, cola, ticket y notificaciones | M1/M2/M3/M5 | Reconexión WebSocket (2.1) |
| Web App Administrativa | React/TS | UI de configuración | M7 | Separación de acceso admin (2.3) |
| API Backend | FastAPI (monolito) | Aloja M1, M2, M3, M5 y M7 | M1–M3, M5, M7 | Stateless tras LB (2.1/2.2), validación (2.3) |
| Worker de Reasignación | Python | Ejecuta M6 en background | M6 | Bulkhead + escalado horizontal (2.1/2.2) |
| Worker de Inactividad | Python | Cancela turnos abandonados | M3 | Heartbeat / fault detection (2.1) |
| Consumers M4/M5 | Python (aio-pika) | Notificación y seguimiento asíncronos | M4/M5 | Reintento/DLQ, bulkhead (2.1) |
| PostgreSQL | postgres:15 | Fuente de verdad | Todos | ACID + réplica + backups (2.1) |
| Redis | redis:7 | Sesiones (M1), cache config (M7), cola operativa (M2) | M1/M2/M7 | TTL + AOF + Cache-Aside (2.1/2.2) |
| RabbitMQ | rabbitmq:3 | Desacople de eventos turno.* + DLQ | M3→M4/M5/M6 | Pub-Sub asíncrono (2.2) |

> El API es un **monolito modular**: los siete módulos comparten proceso, pero los workers (M6, inactividad M3) y los consumers (M4/M5) se despliegan como contenedores separados para aislar fallos (bulkhead) y escalar de forma independiente.
