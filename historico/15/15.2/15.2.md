## Diagrama de Despliegue (nuevo)

<img src="../../resources/img/Nivel4_Despliegue_M2_M3.png">

### Documentación de respaldo por nodo

| Nodo | Tecnología | Propósito y responsabilidades | Despliegue (réplicas / recursos) | Zona / seguridad |
|---|---|---|---|---|
| API Gateway / Reverse Proxy | Nginx/Traefik | Termina TLS, rate limiting, oculta topología | 1+ (activo/standby) | Borde; punto de cifrado |
| Load Balancer | Nginx/LB gestionado | Distribuye REST y mantiene afinidad para WebSocket | Integrado/gestionado | Borde |
| API Backend | FastAPI (Docker) | Endpoints de cola/turno + WebSocket; stateless | ≥ 2 réplicas | Privada |
| Worker de Inactividad | Python (Docker) | Cancela turnos abandonados (heartbeat) | 1 (idempotente; líder único recomendado) | Privada |
| PostgreSQL primario | postgres:15 | Fuente de verdad (`turnos`, `turno_dia`) | 1 primario; volumen persistente | Privada; TLS |
| PostgreSQL réplica | postgres:15 (standby) | HA y descarga de lecturas de estado | 1 standby (streaming) | Privada |
| Backups | WAL + `pg_dump` | Recuperación ante desastre (PITR) | Programados; externo cifrado | Privada/externa |
| Redis | redis:7 (AOF) | Cola operativa (Sorted Set) + contadores; AOF de respaldo | 1 (réplica a futuro) | Privada; TLS |
| RabbitMQ | rabbitmq:3 | Distribuye eventos turno.* a M4/M5/M6 | 1 (clúster a futuro); colas duraderas | Privada |

> **Trazabilidad con Sección 2:** réplicas API + LB (con afinidad WSS) → continuidad/escalabilidad (2.1/2.2); Redis Sorted Set + contadores atómicos con AOF → latencia < 5 ms y recuperación (2.2/2.1); PostgreSQL primario+réplica+backups + `idx_turnos_activo` → consistencia y prevención de inconsistencia (2.1); Worker idempotente (líder único) → heartbeat sin doble cancelación (2.1); gateway + zonas + TLS → control de acceso y cifrado (2.3).

## Actualización de ADRs

| ADR | Estado | Cambio |
|---|---|---|
| **ADR-15.2-M2-002 — Redis como cola operativa con AOF** | Nuevo | La cola virtual vive en Redis (Sorted Set) con AOF; PostgreSQL es la fuente de verdad histórica vía sync con compensación (complementa [ADR-9.2-M2-001](../../9/9.2/9.2.md)). |
| **ADR-15.2-M3-002 — Worker de inactividad como proceso único** | Nuevo | El Scheduler corre como proceso separable; se recomienda elección de líder único para evitar cancelaciones duplicadas (idempotencia + heartbeat, Sec. 2.1). |
| **ADR-15.2-SYS-001 — API stateless con afinidad WebSocket** | Nuevo | API replicable tras LB; el WebSocket requiere afinidad de sesión (sticky) o un bus de presencia compartido. |
| [ADR-9.2-M3-001 — PostgreSQL + Redis para turnos](../../9/9.2/9.2.md) | Actualizado | Se confirma primario+réplica+backups y la invalidación de caché por evento `turno_actualizado`. |
