## 1. Concepto del Patrón

El patrón **Command** es un patrón de comportamiento que encapsula una solicitud como un objeto, permitiendo ejecutar, encolar, registrar y revertir operaciones.

### Problema que resuelve
En sistemas con múltiples servicios acoplados (auth, scraping, notificaciones), el orquestador termina llamando directamente a cada uno:

- Alto acoplamiento  
- Difícil manejo de errores  
- Imposibilidad de rollback estructurado  

### Solución
Cada operación se convierte en un **objeto comando** con:

- `execute()`
- `undo()` (opcional)

El orquestador solo ejecuta comandos sin conocer detalles internos.

---

## 2. Estructura

- **Invoker:** Cola de comandos  
- **Command:** Interfaz común  
- **ConcreteCommand:** Operaciones del sistema UNI  
- **Receiver:** Servicios reales (requests, BeautifulSoup, sesión en memoria)  

---

## 3. Flujo

Invoker → Command → Receiver  
execute()  
undo()

## 4. Aplicación en el Sistema del Comedor UNI

### Casos de uso reales del sistema

- M1: Crear sesión desde cookies (set-session)
- M2: Parsear datos de alumno desde HTML (parse-data)
- M3: Cerrar sesión en el servidor UNI (logout)

---

## Antes (acoplado)

set_session()  
parse_data()  
logout()  

Problema: lógica mezclada en endpoints, sin control de flujo ni rollback.

---

## Después (Command)

cola.agregar(SetSessionCommand(cookies))  
cola.agregar(ParseDataCommand(home_html, cursos_html))  
cola.agregar(LogoutCommand(sid, token))  
cola.ejecutar_todos()

## Implementación base

```python
from abc import ABC, abstractmethod  


class Command(ABC):  
    def execute(self):
        pass  
    def undo(self):
        pass  
```

---

## Concrete Commands (basados en FastAPI)

### M1 — Set Session

```python
class SetSessionCommand(Command):  
    def execute(self):
        self.sid = uuid.uuid4()  
        sessions[self.sid] = {"cookies": self.cookies}  
        return self.sid  

    def undo(self):  
        sessions.pop(self.sid, None)  
```

---

### M2 — Parse Data (BeautifulSoup scraping)

```python
class ParseDataCommand(Command):  
    def execute(self):  
        nombre = BeautifulSoup(self.home_html).select_one(".user-name")  
        codigo = BeautifulSoup(self.home_html).select_one(".user-code")  

        return {  
            "nombre": nombre.get_text(),  
            "codigo": codigo.get_text()  
        }  

    def undo(self):  
        self.result = None  
```

### M3 — Logout (requests HTTP externo)

```python
class LogoutCommand(Command):  
    def execute(self):
        requests.post(  
            "https://alumnos.uni.edu.pe/logout",  
            data={"_token": self.token},  
            cookies=sessions[self.sid]["cookies"]  
        )  

        sessions.pop(self.sid, None)  

    def undo(self):  
        sessions[self.sid] = {"cookies": self.backup}  
```

## Invoker (Cola)
```python
class ColaComandos:  
    def ejecutar_todos(self):  
        for c in self.comandos:  
            if not c.execute():  
                self.rollback()  
                return  
```

## Beneficios

- Bajo acoplamiento entre FastAPI y lógica interna  
- Permite encadenar scraping + sesión + logout  
- Facilita auditoría de acciones del usuario  
- Posibilidad de rollback parcial (undo de sesión o parsing)  
- Extensible a colas (RabbitMQ / Celery)  

---

## Limitaciones

- Mayor número de clases  
- Undo limitado en operaciones HTTP externas  
- Complejidad inicial mayor  

---

## Relación con otros patrones

- **Pub/Sub:** logout puede disparar eventos de notificación  
- **Memento:** guardar estado de sesión antes de logout  
- **Chain of Responsibility:** validación de sesión antes de ejecutar comandos  

---

## Conclusión

El patrón Command permite transformar el backend de FastAPI en un sistema modular donde:

- set-session, parse-data y logout dejan de ser funciones sueltas  
- pasan a ser objetos ejecutables y trazables  
- se mejora escalabilidad, mantenimiento y control del flujo  

En el sistema del comedor UNI, esto permite orquestar autenticación, scraping y cierre de sesión sin acoplamiento directo entre módulos.
