# 17.3. Módulo 3 / Integrante 3

**Módulos cubiertos:** M6 – Reasignación de Turnos · M7 – Configuración Operativa

Esta sección documenta los escenarios de calidad que el prototipo aborda **en el código** (no solo en el diseño), con trazabilidad completa: escenario → táctica implementada → estructura C4 → código que la materializa → forma de verificarlo. Se priorizan los escenarios que motivaron las tácticas de la [Sección 2](../../14/14.3/14.3.md).

---

## Escenarios abordados en el código

| # | Escenario de calidad | Atributo | Táctica / solución implementada | Estructura C4 que lo soporta | Evidencia en el código | Forma de verificarlo |
|---|---|---|---|---|---|---|
| 1 | El admin envía un turno con horarios cruzados (`apertura > cierre`) | Seguridad / Integridad | Validación de entrada antes de persistir; `400` | API Backend → `config.service` (Componentes M7, [15.3](../../15/15.3/15.3.md)) | [`config/service.py`](../../s111-actividad-bosquejo-implementacion/backend/src/modules/config/service.py) → `_validate_horas` | `PUT .../config/turnos/ALMUERZO` con horas cruzadas → `400` |

| 3 | El admin envía `raciones_max <= 0` | Seguridad / Integridad | Validación de rango; no persiste | `config.service` → PostgreSQL | [`config/service.py`](../../s111-actividad-bosquejo-implementacion/backend/src/modules/config/service.py) → `update_turno_config` | `PUT .../config/turnos/CENA -d '{"raciones_max":0}'` → `400` |
| 4 | Se actualiza un turno inexistente | Continuidad / Manejo de errores | Verificación previa + `404` (sin escritura parcial) | `config.service` → PostgreSQL (`turnos_config`) | [`config/service.py`](../../s111-actividad-bosquejo-implementacion/backend/src/modules/config/service.py) → `get_turno_config` | `GET/PUT .../config/turnos/MERIENDA` → `404` |
| 5 | El admin solo cambia un campo y el resto debe conservarse | Usabilidad / Integridad | Actualización parcial (`exclude_unset`): merge con la fila vigente | `config.router` → `config.service` | [`config/router.py`](../../s111-actividad-bosquejo-implementacion/backend/src/modules/config/router.py) → `model_dump(exclude_unset=True)` | `PUT` con solo `raciones_max`; los horarios no cambian |
| 6 | Se registra un menú para una fecha que ya tiene menú | Consistencia | Rechazo de duplicado con `409` | `config.router` (menú) → PostgreSQL | [`menu/service.py`](../../s111-actividad-bosquejo-implementacion/backend/src/modules/menu/service.py) → `create_menu_dia` (chequea existencia) | `POST /config/menu` dos veces misma fecha → `409` |
| 7 | Se registra un menú con un `tipo_comida` inválido | Seguridad / Integridad | Validación de tipos de comida permitidos; `400` | `menu.service` | [`menu/service.py`](../../s111-actividad-bosquejo-implementacion/backend/src/modules/menu/service.py) → `_validate_comidas` (`VALID_TIPOS`) | `POST /config/menu` con `tipo_comida:"X"` → `400` |
| 8 | Se edita el menú de una fecha sin menú | Continuidad / Manejo de errores | `404` controlado | `menu.service` → PostgreSQL | [`menu/service.py`](../../s111-actividad-bosquejo-implementacion/backend/src/modules/menu/service.py) → `update_menu_dia` | `PUT /config/menu?fecha=2099-01-01` → `404` |
| 9 | El estudiante consulta el menú sin indicar fecha | Usabilidad | Valor por defecto: fecha actual en hora de Perú (UTC-5) | `config.router` (menú) | [`config/router.py`](../../s111-actividad-bosquejo-implementacion/backend/src/modules/config/router.py) → `fecha or fecha_peru()` | `GET /config/menu` (sin `fecha`) → menú de hoy |
| 10 | El evento de cupo liberado se reprocesa (reentrega / doble disparo) | Continuidad / Disponibilidad | **Idempotencia**: no actúa si ya hay un grupo en `LLAMADO` | Worker de Reasignación (Componentes M6, [15.3](../../15/15.3/15.3.md)) | [`reassignment/service.py`](../../s111-actividad-bosquejo-implementacion/backend/src/modules/reassignment/service.py) → guard `COUNT(... estado='LLAMADO') > 0` | Disparar la reasignación dos veces: la 2.ª retorna lista vacía |
| 11 | Dos disparos concurrentes intentan llamar al mismo grupo | Continuidad / Consistencia | **Transición atómica condicionada** (`UPDATE ... WHERE estado='ESPERANDO'`) | Worker de Reasignación → PostgreSQL (`turnos`) | [`reassignment/service.py`](../../s111-actividad-bosquejo-implementacion/backend/src/modules/reassignment/service.py) → `UPDATE ... WHERE estado='ESPERANDO'` | Solo los `ESPERANDO` pasan a `LLAMADO`; sin doble transición |
| 12 | No quedan turnos en espera al disparar la reasignación | Continuidad / Manejo de errores | Salida segura: retorna vacío si no hay `ESPERANDO` | Worker de Reasignación | [`reassignment/service.py`](../../s111-actividad-bosquejo-implementacion/backend/src/modules/reassignment/service.py) → `MIN(numero_turno) ... is None` | Cola vacía: la reasignación retorna `[]` sin error |
| 13 | El llamado se hace por lotes según el aforo (no uno a uno) | Escalabilidad / Rendimiento | Tamaño de grupo derivado del aforo (`batch_size = ceil(raciones_max/10)`) | Worker de Reasignación | [`reassignment/service.py`](../../s111-actividad-bosquejo-implementacion/backend/src/modules/reassignment/service.py) → cálculo de `batch_size` y rango `[pos_inicio, pos_fin]` | Con `raciones_max=5000`, se llama en grupos de 500 |
| 14 | Un atacante intenta forzar reasignaciones desde fuera | Seguridad / Reducir superficie | M6 **sin endpoints HTTP**: solo se invoca internamente | Worker de Reasignación (sin router) | Ausencia de `router.py` en [`reassignment/`](../../s111-actividad-bosquejo-implementacion/backend/src/modules/reassignment/) | `grep -c "/reassignment" openapi.yaml` → `0` |

## Detalle por escenario

### Escenarios 1–5 — Validación y actualización de configuración (M7)

`config.service` valida en la capa de servicio antes de tocar la BD y hace `rollback` ante error; el `PUT` es parcial (solo cambia lo enviado). Materializa **validación de entrada** y manejo de errores (Sec. 2.3/2.1).

```python
# config/service.py (extracto)
CONFIGURABLE_TIPOS = {"ALMUERZO", "CENA"}

def _validate_tipo(tipo):
    if tipo.upper() not in CONFIGURABLE_TIPOS:
        raise HTTPException(status_code=400, detail=...)

def _validate_horas(apertura, inicio, cierre):
    if not (apertura <= inicio <= cierre):
        raise HTTPException(status_code=400, detail=...)

# config/router.py (extracto) - actualizacion parcial
return update_turno_config(tipo, payload.model_dump(exclude_unset=True))
```

**Verificación (backend levantado, ver [16.3](../../16/16.3/16.3.md)):**
```bash
curl -s -o /dev/null -w "%{http_code}\n" -X PUT http://localhost:8000/config/turnos/ALMUERZO \
  -H "Content-Type: application/json" -d '{"hora_apertura":"09:00:00","hora_cierre":"08:00:00"}'   # 400
curl -s -o /dev/null -w "%{http_code}\n" -X PUT http://localhost:8000/config/turnos/PRUEBA \
  -H "Content-Type: application/json" -d '{"raciones_max":10}'                                       # 400
```

### Escenarios 10–14 — Reasignación idempotente, atómica y por lotes (M6)

```python
# reassignment/service.py (extracto)
cur.execute("SELECT COUNT(*) FROM turnos WHERE turno_dia_id=%s AND estado='LLAMADO'", (turno_dia_id,))
if cur.fetchone()[0] > 0:
    return []                                   # idempotencia
...
batch_size = max(1, math.ceil(raciones_max / 10))   # llamado por lotes segun aforo
...
cur.execute("""
    UPDATE turnos t SET estado='LLAMADO', llamado_at=NOW()
    WHERE t.turno_dia_id=%s AND t.numero_turno BETWEEN %s AND %s
      AND t.estado='ESPERANDO'                  # transicion atomica condicionada
    RETURNING ...
""", (turno_dia_id, pos_inicio, pos_fin))
```

**Verificación:** ejecutar el flujo de cola ([16.2](../../16/16.2/16.2.md)) hasta dejar un grupo en `LLAMADO`; un segundo disparo de reasignación retorna vacío y no duplica llamados. Para la superficie de ataque:

```bash
grep -c "/reassignment" openapi.yaml    # 0
```
