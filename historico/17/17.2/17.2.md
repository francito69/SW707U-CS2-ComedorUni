# 17.2. Módulo 2 / Integrante 2

**Módulos cubiertos:** M2 – Gestión de Colas · M3 – Gestión de Turnos

Esta sección documenta los escenarios de calidad que el prototipo aborda **en el código** (no solo en el diseño), con trazabilidad completa: escenario → táctica implementada → estructura C4 → código que la materializa → forma de verificarlo. Se priorizan los escenarios que motivaron las tácticas de la [Sección 2](../../14/14.2/14.2.md).

---

## Escenarios abordados en el código

| # | Escenario de calidad | Atributo | Táctica / solución implementada | Estructura C4 que lo soporta | Evidencia en el código | Forma de verificarlo |
|---|---|---|---|---|---|---|
| 1 | Una petición de cola usa un `sid` inválido/expirado | Seguridad | Guard de sesión antes de la lógica de cola; `401` | API Backend → Validador de Restricciones (Componentes M2/M3, [15.2](../../15/15.2/15.2.md)) | [`queues/router.py`](../../s111-actividad-bosquejo-implementacion/backend/src/modules/queues/router.py) → `_require_session` | `POST /queue/join` con `sid` falso → `401` |
| 2 | Un estudiante intenta tomar un segundo turno el mismo día | Consistencia / Integridad | Verificación de turno activo + índice único parcial en BD | Gestor de Estado de Turno → PostgreSQL | [`queues/service.py`](../../s111-actividad-bosquejo-implementacion/backend/src/modules/queues/service.py) → `turno_existente`; [`001_init.sql`](../../s111-actividad-bosquejo-implementacion/backend/migrations/001_init.sql) → `idx_turnos_activo` | Encolar dos veces el mismo `sid` → `409` |
| 3 | Un estudiante es llamado pero abandona; su cupo no debe bloquearse | Continuidad / Disponibilidad | Monitoreo por heartbeat (`ultimo_ping`): worker cancela `LLAMADO` sin ping en 3 min | Scheduler de Activación (worker) → PostgreSQL | [`queues/worker.py`](../../s111-actividad-bosquejo-implementacion/backend/src/modules/queues/worker.py) → `cancelar_inactivos` | Dejar un turno `LLAMADO` sin ping > 3 min → pasa a `CANCELADO` |
| 4 | Se intenta encolar cuando no hay turno habilitado | Continuidad / Manejo de errores | Validación de turno activo; `503`/`400` controlado | `queue.router` → `turno_dia` | [`queues/router.py`](../../s111-actividad-bosquejo-implementacion/backend/src/modules/queues/router.py) → `join` | `POST /queue/join` sin `turno_dia` habilitado → `503` |
| 5 | El aforo del turno se agota | Disponibilidad / Integridad | Control de capacidad: se rechaza el ingreso si no hay raciones | Control de Capacidad → PostgreSQL | [`queues/service.py`](../../s111-actividad-bosquejo-implementacion/backend/src/modules/queues/service.py) → `raciones_usadas` / `get_raciones_max_turno_dia` | Encolar hasta llenar el aforo → siguiente `join` → `400` |
| 6 | El orden de atención debe respetar la llegada (FIFO) | Consistencia / Integridad | Posición por `numero_turno` incremental; el conteo excluye `CANCELADO` | Gestor FIFO → PostgreSQL | [`queues/service.py`](../../s111-actividad-bosquejo-implementacion/backend/src/modules/queues/service.py) → `siguiente_numero`, `posicion_en_cola` | `GET /queue/status`: la posición refleja el orden de ingreso |
| 7 | El estudiante sale de la cola (acción repetible) | Continuidad / Idempotencia | `leave` no falla si no hay turno; `cancelar_turno` condicionado por estado | `queue.router` → PostgreSQL | [`queues/router.py`](../../s111-actividad-bosquejo-implementacion/backend/src/modules/queues/router.py) → `leave_queue`; [`service.py`](../../s111-actividad-bosquejo-implementacion/backend/src/modules/queues/service.py) → `cancelar_turno` (`WHERE estado NOT IN ('ATENDIDO','CANCELADO')`) | `POST /queue/leave` dos veces → `200` ambas, sin error |
| 8 | Se confirma un turno ya finalizado (ATENDIDO/CANCELADO) | Consistencia / Manejo de errores | Rechazo con `400` según el estado actual | Gestor de Estado de Turno | [`queues/router.py`](../../s111-actividad-bosquejo-implementacion/backend/src/modules/queues/router.py) → `confirm_presence` (`if turno["estado"] in (...)`) | `POST /queue/confirm` sobre un turno ATENDIDO → `400` |
| 9 | Una conexión WebSocket usa un `sid` inválido | Seguridad | Cierre inmediato del socket con código de control | RealTime / `queue.ws` | [`queues/router.py`](../../s111-actividad-bosquejo-implementacion/backend/src/modules/queues/router.py) → `queue_websocket` (`ws.close(code=4001)`) | Conectar a `ws://.../queue/ws/<sid_falso>` → cierre `4001` |
| 10 | El estudiante confirma presencia y debe avanzar la fila | Escalabilidad / Coordinación | Tras `ATENDIDO`, se publica evento y se llama al siguiente grupo (M6) | Gestor de Estado → RabbitMQ / Worker | [`queues/router.py`](../../s111-actividad-bosquejo-implementacion/backend/src/modules/queues/router.py) → `confirm_presence` (`publish` + `llamar_siguiente`) | Confirmar un turno; observar `turno.atendido`/`turno.llamado` en RabbitMQ (`15672`) |

## Detalle por escenario

### Escenarios 1–2 — Sesión y unicidad de turno

```python
# queues/router.py (extracto)
def _require_session(sid: str) -> dict:
    session = get_session(sid)
    if not session:
        raise HTTPException(status_code=401, detail="Sesión inválida o expirada")
    return session
```

```sql
-- 001_init.sql: un solo turno activo por estudiante/dia (permite cancelados)
CREATE UNIQUE INDEX IF NOT EXISTS idx_turnos_activo
ON turnos (estudiante_id, turno_dia_id)
WHERE estado != 'CANCELADO';
```

**Verificación (backend levantado, ver [16.2](../../16/16.2/16.2.md)):**
```bash
curl -s -o /dev/null -w "%{http_code}\n" -X POST http://localhost:8000/queue/join \
  -H "Content-Type: application/json" -d '{"sid":"falso"}'          # 401
# encolar dos veces el mismo sid valido -> el segundo responde 409
```

### Escenarios 3, 7, 8 — Ciclo de vida robusto del turno (M3)

```python
# queues/service.py (extracto)
def cancelar_turno(turno_id):
    cur.execute("""
        UPDATE turnos SET estado='CANCELADO', cancelado_at=NOW()
        WHERE id=%s AND estado NOT IN ('ATENDIDO','CANCELADO')   # idempotente
    """, (turno_id,))

# queues/router.py - confirm_presence (extracto)
if turno["estado"] in ("ATENDIDO", "CANCELADO"):
    raise HTTPException(status_code=400, detail=f"Tu turno está {turno['estado']}")
```

El worker de inactividad ([`worker.py`](../../s111-actividad-bosquejo-implementacion/backend/src/modules/queues/worker.py)) cancela los `LLAMADO` sin ping en 3 min vía `cancelar_inactivos`, liberando el cupo (detección de fallos por heartbeat).
